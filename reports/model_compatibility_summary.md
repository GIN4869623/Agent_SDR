# 本地模型与 Agent Loop 兼容性评测

评测日期：2026-08-24

## 结论

| 模型 | 协议兼容 | 功能得分 | 完全通过 | 平均耗时 | 中位耗时 | 判断 |
|---|---:|---:|---:|---:|---:|---|
| `qwen3.5:35b` | 是 | 100/100 | 8/8 | 8.76 秒 | 7.11 秒 | 高度兼容，当前优先推荐 |
| `qwen3.5:122b` | 是 | 98.75/100 | 7/8 | 31.34 秒 | 29.03 秒 | 基本兼容，较慢且有一次结果忠实度缺失 |

两个模型均正确支持当前 Loop 所要求的 OpenAI 流式 Chat Completions、结构化
`tool_calls`、`tool_choice=required/auto`、JSON 参数和工具结果续写。

35B 在本轮样本中全部通过，且平均案例耗时约为 122B 的 28%。就当前受 Skill 和代码
边界约束的 Agent Loop 而言，35B 的能力已经足够，并具有明显的交互延迟优势。

122B 唯一未完全通过的是“本地知识库为空后回退联网搜索”案例。它正确完成了
`search_sdr_knowledge -> web_search -> 最终回答`，工具顺序、查询参数和任务状态均正确，
但最终回答没有采用模拟网络结果中的标记 `W17`，反而概括为没有找到有效定义，因此
结果忠实度项扣 10 分。这不是协议故障，而是工具结果利用不充分。

## 案例范围

1. 普通对话不调用工具。
2. 扫频工具选择及 GHz/MHz 到 Hz 的单位换算。
3. 中文文本、QPSK、中心频率和收发增益提取。
4. 自适应调制意图与参数提取。
5. 认知选频、禁止文本发送和 Tone 可视化复合参数。
6. 本地知识检索及回答依据约束。
7. 本地知识库空结果后的联网回退工作流。
8. 工具返回错误时如实说明失败。

评测使用生产 `AgentLoop`、Router、Skill 和 MCP 工具 Schema，但工具执行结果全部由
安全模拟器返回，没有连接 USRP、启动 VLC、访问真实知识库或执行真实联网搜索。

## 限制与下一步

本报告每个模型、每个案例只运行了一次，适合判断基础兼容性，不代表长期稳定率。
上线前建议使用 `--repeat 3` 或更高次数复测，并增加多轮会话、提示词注入、长上下文、
参数边界和模型服务并发压力案例。真实 USRP 联调应单独评价硬件可靠性，不要与模型
工具调用能力混为一个分数。
